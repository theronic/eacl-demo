# DataScript explorer entry

Separate build entry and ClojureScript-to-JavaScript Web Worker for the browser-memory profile. It is a JavaScript worker, not a WebAssembly runtime. The entry renders `apps/explorer-main/src/App.tsx`, `Explorer.tsx`, and that directory's exact `components/*` and `styles.css`; it has no presentation component or stylesheet of its own. Only the DataScript transport wiring differs. The DataScript database, EACL adapter, cursor registry, cache, and dispatch remain worker-owned.

`npm run build:datascript-entry` produces the independently based `/datascript/` static entry. `npm run build:datascript-worker` fetches the exact SHA in `dependencies/eacl-core.lock.json` into the ignored build cache, runs the pinned Core source-preparation task, and compiles `eacl-demo.datascript.worker` with advanced optimizations. It injects the locked Core SHA as a Closure define and fails if the output retains an unconfigured identity. It never reads the sibling EACL checkout.

`npm run build:static-site` gives the worker a full-digest name such as `datascript/assets/datascript-worker-<sha256>.js`; there is no mutable worker URL. The browser fetches the exact independently published DataScript profile, verifies its content address and closed profile mapping, then fetches only that same-origin digest path with redirects disabled, credentials omitted, `no-store`, a JavaScript media type, and a 4 MiB streaming cap. It hashes the received bytes before constructing a short-lived Blob worker and immediately revokes the Blob URL. Static publication must retain any digest path referenced by a live or rollback-eligible profile publication.

Before any operation, an `initialize` handshake binds the worker lifecycle to the publication's exact profile, demo SHA, compiled Core SHA, worker digest, deployment ID, and fixture-manifest digest. The worker independently requires its compiled Core SHA and canonical fixture digest to match. Every response repeats that identity and exact request/operation correlation; any drift fails closed.

The worker constructs both `eacl.datascript.core/create-conn` and `eacl.datascript.core/make-client`, then verifies the result through the public `eacl.core/acl?` API. Its closed initialize, request, cancel, reset, response, progress, initialized, and protocol-error messages carry deterministic request IDs and bounded client epochs. A reset invalidates old replies and releases the old worker-owned database/index/cache/cursor graph while retaining the immutable lifecycle identity.

The canonical Clojure/ClojureScript generator seeds objects before relationships in one worker-local import. JVM digest tests prove its 48,693 canonical records reproduce the accepted semantic and full fixture SHA-256 values; the browser reports progress and exposes readiness only after the exact 10,000-resource cut point completes.

The closed dispatcher implements the complete shared read-only surface: health, bootstrap, subjects, object lookup, outbound relationships, reverse relationships, `lookup-resources`, `count-resources`, `lookup-subjects`, authorization, schema, cache facts, and bounded physical counts. The EACL operations report worker-measured elapsed time and hit/miss/disabled cache provenance for the canonical Explorer timing badges. Inputs are validated and normalized from language-neutral wire strings to EACL keyword identifiers only at the worker boundary. Pagination uses EACL cursors for authorization lookups and opaque random worker-lifecycle tokens for fixture browsing; all are destroyed by worker replacement.

Both allowed and denied exemplars call `eacl.core/check-permission` against the worker-owned client and return a normalized `explorer.v1` decision. `verification/datascript/browser-local.spec.ts` verifies the content-addressed publication/worker request chain, the exact Backend/Storage selector, the canonical Subjects/Resources/Detail layout, EACL lookup/count/permission operations, timing/cache badges, and an empty network log after readiness.

`npm run verify:datascript-isolation` inspects the main Vite entry graph, source map, output paths, and JavaScript markers, while requiring the corresponding CLJS/EACL witnesses in the dedicated worker. `verification/datascript/main-network-isolation.spec.ts` independently proves that opening `/` never fetches `/datascript/`, the worker, or the generated EACL browser kernel.
